# Internationalization

**i18n status: Applies.** This project publishes a page about California educator credentials
for a California audience, which is squarely the civic surface the portfolio's
internationalization standard binds. It is not exempt, and it is not English-only by right.

**implementation: none yet.** Every string the page prints on its own account is an inline
literal in `src/chalkline/site.py`, with the two disclaimer strings in
`src/chalkline/ctdl/export.py` because the JSON-LD and the coverage statement carry them too.
There is no catalog, no locale directory, no second edition, and no parity check. The page is
served as `<html lang="en">` and the emitted licenses carry `ceterms:inLanguage` of `en-US`,
both of which are correct statements about what this project publishes today.

**Declared: 2026-09-05. Reviewer: Chelsea Kelly-Reif, sole maintainer. There is no
independent reviewer and nothing here should be read as though there were.**

This file is the scope declaration, and it is written before the catalog on purpose. This
project has a constraint most of the portfolio's bilingual surfaces do not: its entire input
is one state agency's English-language publications, and the names in it are the names a
person has to use to look a credential up. Deciding what a catalog may touch is therefore the
hard part of the work, not the setup, and doing it first is what makes the boundary a
declaration rather than an accident of whichever strings somebody happened to extract.

## The three kinds of string on this page

### 1. This project's own words. Translatable.

Everything the page says on its own account, which is everything that is not quoted from the
Commission. It is all in `src/chalkline/site.py` except where noted:

- The document head: `TITLE`, `DESCRIPTION`, and `CARD_ALT`, which are the tab title, the
  meta description, and the share card's alternative text.
- The heading, and the paragraph under it that names the sources and their retrieval dates.
- The unofficial notice: `DISCLAIMER_LEAD` and `DISCLAIMER_BODY` in
  `src/chalkline/ctdl/export.py`. These are the one set of strings shared with the artifacts,
  since the JSON-LD carries the pair as its `comment` and `coverage.json` as its `note`. A
  second edition would have to decide whether a Spanish page quotes a Spanish disclaimer over
  an English artifact, and the answer is not obvious.
- The paragraph stating that an absence on this page is the state of the published source
  rather than an omission being smoothed over.
- The labels under the counts in `_counts_block`. The figures beside them are numbers and are
  not catalog content.
- The two section headings, the paragraph explaining what is not modeled, and the footer.
- The exclusions table's accessible name and its four column headers, in `_exclusions_table`.
- The per-credential furniture in `_credential_block`: the words `document`, `authorization`,
  and `CTID` beside the Commission's values, and the link text `Authorization Sort Table` and
  `Leaflet`.
- Every sentence this project writes in place of something the Commission did not publish:
  the two no-description sentences, the not-subject-coded sentence, the no-subjects sentence,
  and the no-requirements sentence.
- The `Requirements` and `Renewal and validity` labels on the collapsible sections, and the
  sentence in `_conditions_block` explaining that a leaflet stated no requirements under the
  qualifier the Commission publishes in this authorization's own title.
- The sentence in `_resolution_block` that explains a cross-reference: which note was
  followed, which credential and document it led to, and how many subjects each code
  supplied.
- The one plural on the page, `authorized subject` against `authorized subjects`. It is
  currently a two-branch conditional on the count, which is correct for English and is not a
  plural rule. A catalog would have to carry this as a plural form rather than as two
  strings, because a language with more than two plural categories cannot be served by an
  `if`.

### 2. The Commission's words. Quoted verbatim, never translated.

None of this is catalog content, in any edition, and that is the declaration this project
most needs to make:

- **Credential and document titles.** `Multiple Subject Teaching Credential` is the string a
  person types into the Commission's own search, prints on a form, and reads on a document.
  A translated credential name is a name the Commission does not use and no reader can look
  up, and putting one on this page would invent a Spanish credential vocabulary for
  California that does not exist. The whole leaflet-matching apparatus in this repository
  turns on character-for-character equality against these strings; a translation would not
  merely be unhelpful, it would break the only evidence the attachments rest on.
- **Document codes and authorization codes**, such as `R1E`, and leaflet codes such as
  `CL-902`.
- **Subject codes and subject names**, and the Commission's row notes.
- **The literal `NONE`** in the Subject Code column. The page quotes it in a `<code>` element
  because it is the Commission's published statement that an authorization is not
  subject-coded, and it is a different thing from an empty column. The sentence around it is
  this project's and is translatable; the token is not.
- **Leaflet prose**: descriptions, requirement blocks, and renewal terms, all read from the
  Commission's pages and reproduced under the Commission's own headings. The heading names
  are the Commission's too.
- **URLs**, and the retrieval dates beside them.

The rule, stated once: if a string arrived from `data/source/`, it is quoted source and it
stays in the language the Commission published it in. If a string was written in this
repository, it is a candidate for the catalog. A Spanish edition of this page would therefore
be Spanish framing around English credential names, which is what a bilingual California
credential page honestly looks like, and is the same thing a Spanish-language Commission
publication does with the names of its own documents.

### 3. This project's words that live in the artifacts. The unsolved part.

The awkward middle, named rather than skipped, because it is the reason a catalog cannot just
be extracted from the renderer and called done. These strings were written in this
repository, so by the rule above they are translatable, but they are produced by the modeling
layer and travel in `site/credentials.jsonld` and `site/coverage.json` as data before the
page reads them back:

- **Exclusion reasons**, built in `src/chalkline/model.py` by `_exclusion_reason` and
  `reason_unfollowable`. Every one of them is printed in the "Not modeled, and why" table and
  is also a published field of the coverage statement.
- **Match rules and the evidence they cite**: `MATCH_EXACT_TITLE`, `MATCH_NAMED_FAMILY`,
  `FROM_INDEX`, `FROM_PAGE`, and `FROM_DOCUMENT_CODE` in
  `src/chalkline/sources/leaflets.py`, which the page prints in parentheses beside a leaflet
  link and the coverage statement counts by.
- **Refusal reasons** for a leaflet page this project declined to read, which the page prints
  and `PROVENANCE.md` records.

Translating them where they are written would give each language its own
`credentials.jsonld` and its own `coverage.json`, which is the opposite of two editions
rendering from one artifact, and it would make `chalkline check` a check per language.
Leaving them where they are and translating only the renderer would print Spanish framing
around English reason strings. Neither is acceptable as it stands, so the catalog work has to
decide this first, and this file records the decision as open rather than pretending the
renderer is the whole surface.

## What is not built

- **No catalog.** No `locales/` directory, no `.po` files, no keyed mapping. The strings in
  category 1 are inline literals.
- **No key parity, placeholder parity, or pseudolocale check**, because there is no second
  edition to hold to a first.
- **No language negotiation.** One page, one language, `lang="en"` in the markup.
  `tests/test_accessibility.py` checks that the `<html>` element declares a language, which
  is the WCAG requirement and is not an i18n mechanism.
- **No locale-aware number formatting.** The counts on the page are written one way, and if a
  second edition is built they should stay written one way, so that a figure copied out of
  either edition is the same figure. That will be a deliberate departure from the standard's
  usual expectation, and it should be recorded as one when the time comes.

## What has to be true before a Spanish edition exists

The blocking work is not code.

A Spanish edition needs a translation reviewed by somebody who reads Spanish, sitting with
the page and checking that each framing sentence still says what the English credential name
beside it means. That is a harder review than it sounds: several of the strings in category 1
exist precisely to explain why something is absent, and a translation that softens "this
project does not compose one" into "no description is available" would turn a statement about
this project's refusal into a statement about the Commission's publication. A generated
translation shipped as though it were reviewed would be exactly the defect this repository is
built to avoid, which is a plausible-looking output detached from the evidence it claims to
rest on, and it will not be published here.

Until then this row is declared, not met. The README's Internationalization row says so, the
metrics ledger lists it among the rows that are open, and issue #63 tracks the remaining work:
resolve category 3, build the catalog for category 1, and gate parity.
